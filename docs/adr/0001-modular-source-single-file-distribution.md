# ADR 0001 — קוד מקור מודולרי, הפצה כקובץ HTML יחיד

**מצב:** התקבל · 2026-11-11 · מחליף את `AGENTS.md` §2.5 ואת `DEVELOPERS.md` §1.4

## הקשר

בגרסה 3 כל הכלי, כולל הבדיקות, יושב בקובץ `index.html` אחד (7,795 שורות, 1.46MB).
הכלל "אין build, אין קבצים נוספים" נועד להבטיח דבר אחד: המשתמש מוריד קובץ אחד
ועובד בלי רשת. אבל הכלל ערבב בין שני דברים שונים:

1. **מה המשתמש מקבל.** קובץ אחד, אופליין, לחיצה כפולה. זו דרישה נכונה ונשארת.
2. **איך הקוד כתוב.** קובץ ענק אחד, בלי טיפוסים, עם שורות base64 שעורכים נחנקים
   עליהן ובדיקות שחיות בתוך קוד הייצור. זה כבר מגביל את התחזוקה, ובוודאי את
   ההרחבה שנדרשת בשכתוב (סכמות 1–7, דחיסה, מנועי התאמה, Workers).

## החלטה

- קוד המקור מחולק למודולים עם אחריות ברורה (`src/core`, `src/database`, `src/linking`…).
- שלב build הופך אותם לקובץ **אחד**, `OtzariaLinker.html`. כל JS, CSS, SVG ו־WASM
  מוטמעים בו, והוא נפתח מ־`file://` בלי שרת ובלי רשת.
- הבדיקות יוצאות מקוד הייצור ל־`tests/`.
- הקובץ `legacy/OtzariaLinker-v3.html` נשמר בלי שינוי (byte-exact, ראו `.gitattributes`)
  כבסיס רגרסיה, עד שגרסה 4.0 תעבור את תנאי הקבלה.

## מה נשאר מחייב מהכללים הישנים

- אפס בקשות רשת אוטומטיות. נאכף ב־`scripts/package-release.mjs` (סריקה סטטית של
  התוצר) ובבדיקת E2E שרצה כשהרשת מנותקת.
- אין כתיבה לקובצי מסד הנתונים של המשתמש.
- `"Conection Type"` עם n אחת.
- אין פונט אייקונים ואין משאב חיצוני.

## השלכות

- למפתח נדרשים Node 22 ומעלה ו־`npm ci`. למשתמש לא נדרש כלום.
- `AGENTS.md` ו־`DEVELOPERS.md` ייכתבו מחדש (שלב 22). עד אז ה־ADR הזה גובר עליהם.
- יש ל־Release תוצר שנבנה, ולכן אפשר לשחזר אותו מאותו commit (ADR 0002).
