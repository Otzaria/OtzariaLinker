## 2. הערות לפי מאגר

### 2.1 Otzaria/otzaria-link-generator (`7ad8b2c3e49466c437218955b18a487cdc05d805`, push אחרון 2026-10-08)

**מה זה באמת.**
- זה תוסף אוצריא (`manifest.json`: `com.otzaria.links-generator` 3.0.0, `minAppVersion 0.9.97`, `network.enabled:false`), ובמקביל אפליקציית React/Vite עם `vite-plugin-singlefile`.
- הוא מקשר **פירוש לטקסט מקור** לפי דיבור המתחיל, עם עורך ידני (גרירה לקישור מחדש) ופרויקטים שמורים.
- תלויות: React 19, motion, lucide, jszip. יש גם `@google/genai` ו־`express`: לא ראיתי שימוש בהם בליבת המנוע, אבל אסור שייכנסו לבנייה שלנו.

**נרמול (`parserAlgorithm.ts` שורות 571–595).**
1. `stripHtmlTags` מחליף תגיות ברווח.
2. `normalizeHebrewQuotes`: `''`→`"`, `׳'’‘´`→`'`, `״"“”″‟„`→`"`.
3. מוחק את U+0591–U+05C7.
4. כל מה שאינו אות עברית, ספרה, `'` או `"` הופך לרווח.
5. `stripEdgeQuotes` מוריד גרשיים שעוטפים מילה ומשאיר גרשיים של ראשי תיבות.

- **באג:** U+05BE (מקף) ו־U+05C3 (סוף פסוק) נמחקים בשלב 3 לפני שהם יכולים להפוך לרווח, ולכן "כל־האדם" הופך ל־"כלהאדם".
- דווקא `searchNormalize.ts` (שורה 23) ממיר מקף לרווח. כלומר יש במאגר שני נרמולים שונים.

**דמיון מילים (`fuzzyUtils.ts`).**
- הציונים: זהות 1.0, שורש אחרי קילוף קידומת 0.92, כתיב מלא/חסר 0.90, Levenshtein על השורשים.
- ספי Levenshtein: מילה של עד 3 אותיות חייבת התאמה מדויקת, 4–6 אותיות מרשות עריכה אחת, 7 ומעלה שתיים. ציון מתחת ל־0.75 נזרק.
- שלד: הסרת ו/י, ואחריה איחוד סופיות א↔ה ו־ן↔ם רק כשנשארו לפחות 3 אותיות. ההערה בקוד מסבירה שבלי הסף הזה לא≡לה.
- **באג:** `PREFIX_LETTER_RE = /^[ובלמשכה]+/` חמדני. "לבית" מקולף ל־"ית", שקצר מ־3, ולכן נשאר "לבית"; "בית" מקולף ל־"ית" ונשאר "בית". שני השורשים שונים, והציון 0.92 לא ניתן.
  - `Util.Heb` הנוכחי כבר מקלף אות אחת בלבד. זה נכון, ואת התיקון הזה צריך לשמר.

**ניקוד וספים (`computeDynamicMinThreshold`, שורות 150–194).**
- לפי מספר המילים:
  - עד 2 מילים: fraction 0.55, floor 0.4;
  - עד 4 מילים: 0.60 / 0.55;
  - יותר: 0.65 / 0.7.
- כשאין מפריד ד"ה מפורש מוסיפים 0.05.
- התקרה 1.5. משקל מילה בודדת מוגבל ל־1.30, ולכן ד"ה של מילה אחת **לא יכול** לעבור את הסף. לכן קיים מסלול נפרד:
- **SWDH** (עוגן חד־מילתי):
  - שוויון מחרוזות בלבד;
  - המילה צריכה להיות נדירה אצל המחבר: לפתוח לכל היותר 0.8% משורותיו (2% בספרי הלכה);
  - המילה צריכה להופיע בשורה אחת בלבד בדף;
  - לפחות 3 אותיות.

**מגיני שווא נוספים.**
- עוגן "רדוד" (3 המילים הראשונות של שורת היעד) מתקבל תמיד. עוגן "עמוק" מתקבל רק עם רצף של לפחות 3 מילים (`PassSpec.deepAnchorMinRun`).
- בצד הפירוש, ההתאמה חייבת להתחיל ב־3 המילים הראשונות.
- רש"י ותוספות: עוגן במילה 0 בלבד (`requireStartAtFirstWord`).
- `pruneConflictingAnchors` ו־`fillGapsBetweenEqualAnchors`: אכיפת מונוטוניות.
- ראשי תיבות בלי גרש/גרשיים לא מורחבים לפי ראשי מילים (BUG-07 בסוף `abbreviations.ts`).
- הרחבה של ראשי תיבות מקבלת משקל מוקטן פי `ABBR_DAMP=0.6`.

**ביטחון (`calculateLinkConfidence`).**
- המאפיינים: כיסוי, אורך רצף, דמיון ממוצע, אינפורמטיביות, מרווח מהמתחרה השני, ביטוי מדויק, מפריד מפורש, דרגת הסולם.
- כיול Platt על 895 קישורים (שלושה זוגות ספרים).
- קישור שעבר בירושה מקבל `parent × retention^depth`.
- זה הרכיב הבשל ביותר שראיתי למדידת ביטחון.

**איכות.**
- יש 65 קבצים תחת `qa/`: בדיקות `*.test.ts`, A/B, בדיקות דיפרנציאליות ושיפוט מול שופט.
- `qa/unit-tests.mjs` מריץ כל קובץ `*.test.ts*` דרך tsx.
- בניגוד לרוב השכנים, זה מאגר שבאמת נבדק.
- ביצועים: Levenshtein על Int32Array משותף, מטמוני מילים עד 200K, ומסמך `PERFORMANCE_WEB_WORKER.md`.

**ייצוא (`exportLinks.ts`).**

**החלטה.** **רעיון בלבד.** הניקוד, ה־`nameOverlap` והמצב השלישי נכנסים למודול "פענוח מראי מקומות". אין לנו `resolveRef`, ולכן צריך פותר משלנו מול ה־TOC של seforim.db.

## 5. התנהגויות סותרות שמנוע אחד חייב ליישב

1. **מספרים עבריים: קפדני מול סוכם.**
   - **הסתירה:** auto-linker ו־LinkerToOtzaria דוחים כל מה שאינו קנוני, אבל tashma ו־Link-Notes מוכיחים שספרים כותבים יה, ער, רחצ.
   - **היישוב:** `parseHebNumber(s, mode)`:
     - `strict` להפניות בתוך פרוזה;
     - `lenient` (סכום) לכותרות מבניות ולסימני הערה;
     - `ordered` (לא עולה) לזיהוי התחלת הפניה.
   - טו/טז וגם יה/יו מתקבלים ב־lenient.

2. **מקף.**
   - **הסתירה:** בשלושה מאגרים המקף נמחק ומילים מתחברות, ב־DhKey הוא הופך לרווח.
   - **היישוב:** תמיד ממירים U+05BE ו־U+05C3 (ו־U+05C0) לרווח **לפני** מחיקת U+0591–05C7. מוסיפים בדיקת יחידה.

3. **אותיות סופיות.**
   - **הסתירה:** בשלד הן מאוחדות, ב־DhKey לא.
   - **היישוב:** שתי פונקציות נפרדות.
     - `dhKey()` נאמנה ל־SeforimLibrary, כדי שאפשר יהיה לשאול את `line_dh`.
     - `matchKey()`/`skeleton()` משמשת לדמיון בלבד.
   - אסור לערבב ביניהן.

4. **גרשיים.**
   - **הסתירה:** מפתחות ההתאמה מסירים גרשיים, אבל פתרון כותר לספר חייב להתאים בדיוק ל־`book.title`, כולל ״ מול " (F18). Link-Notes מתריע על ASCII.
   - **היישוב:** משווים ב־`matchKey`, ואז **פולטים** את `book.title` הקנוני מה־DB, ולא את מה שהמשתמש הקליד.

5. **הרחבת ראשי תיבות.**
   - **הסתירה:** החלפה גלובלית (tashma) מול הרחבה מוגבלת לגרשיים (link-generator) מול רשימה שלילית (LinkerToOtzaria). ר"ל יכול להיות ריש לקיש וגם רוצה לומר.
   - **היישוב:**
     - הרחבה רק לטוקן שמסומן בגרש/גרשיים;
     - כל הרחבה היא **מועמד** עם משקל מוקטן, ולא החלפה;
     - הרשימה השלילית מופעלת לפני הכול.

6. **כינויים קצרים של ספרים.**
   - **הסתירה:** `בק`/`עז`/`במ` בלי גרשיים (auto-linker) וכינויים של 2 אותיות ב־Acronymizer, מול "חסר עדיף על שגוי".
   - **היישוב:** כינוי של 1–3 אותיות מתקבל רק אם:
     - הוא כתוב עם גרשיים, **וגם** אחריו בא מיקום תקין;
     - ואם אין גרשיים — מסומן uncertain.

7. **עמימות.**
   - **הסתירה:** כמעט כולם משמיטים כשיש תיקו, אבל tashma שומר התאמות בביטחון נמוך.
   - **היישוב:** דרגת ביטחון מפורשת:
     - `auto` (מעל הסף, ובלי תיקו) — נכנס אוטומטית;
     - `review` — תור בדיקה;
     - `drop`.
   - שום דבר מתחת לסף לא נכנס בשקט.

8. **בסיס השורות וסוג ההיסט.**
   - **הסתירה:** קבצים הם 1-based, ה־DB ו־LinkerToOtzaria הם 0-based. `start`/`end` גולמיים מול `link_anchor` בתווים נראים. BOM מזיז בתו אחד.
   - **היישוב:**
     - בתוך המנוע: `LineRef {index0}` אחיד, והמרה רק בשכבת ה־IO;
     - ההיסטים נשמרים גם גולמיים וגם נראים, עם `countVisibleChars` (אותה סמנטיקה כמו HtmlCharCounter: ישות = 1, עד 10 תווים ל־`;`);
     - BOM מוסר לפני חישוב.

9. **כיוון הקישור ו־Connection Type.**
   - **הסתירה:** `source` (link-generator), `reference` (auto-linker), `footnotes`, `commentary`. ה־README של auto-linker אומר `linker`.
   - **היישוב:**
     - קובע הכיוון היחיד הוא שם הקובץ;
     - ולידטור חוסם ערבוב בקובץ אחד;
     - הסוג נבחר מרשימה סגורה;
     - בקובץ שנקרא על שם המצטט מתריעים על `commentary`.

10. **דילוג על שורות פתיחה.**
    - **הסתירה:** OLM מדלג על שורות 1–2, PDC רק על 1.
    - **היישוב:** לא מדלגים לפי מספר שורה. מדלגים לפי סוג השורה: כותרת `<hN>`, שורה ריקה, פחות מ־2 אותיות עבריות, תווית `{…}`. אפשר להגדיר "שורת מחבר" בפרופיל.

11. **פיצול פרקים בהערות.**
    - **הסתירה:** OLM דורש מספור רציף לאורך כל הספר, Link-Notes מזהה איפוסים.
    - **היישוב:** כברירת מחדל זיהוי איפוס בנוסח Link-Notes, עם אפשרות לעגן פרקים לכותרות.

12. **פרק בלי פסוק / דף בלי עמוד.**
    - **הסתירה:** auto-linker מקשר לטווח שורות וברירת המחדל שלו עמוד א, ואילו ה־resolve ב־OLM הולך לשורה הראשונה שיש לה heRef.
    - **היישוב:** תמיד `line_index_2` של השורה הראשונה בגוף, ובנוסף `line_index_2_end` (כפי שהפורמט תומך). דף בלי צד ⇒ טווח של שני העמודים, ולא "עמוד א".

## 7. תכנון מנוע מאוחד מומלץ

```
src/engine/
  text/
    normalize.ts      // stage pipeline: html→space (with offset map) → maqaf/sof-pasuk→space → strip U+0591–05C7
                      // → unify quotes → strip edge quotes; returns {text, map}
    keys.ts           // dhKey() (SeforimLibrary contract), refKey(), matchKey(), skeleton(), stem() (single letter)
    hebNumber.ts      // parse(s,{mode:'strict'|'lenient'|'ordered'}), format(n) incl. 15/16; Arabic numerals
    similarity.ts     // wordSimilarity (from fuzzyUtils, prefix fix), levenshtein (Int32Array)
    weights.ts        // stop words + length weight + IDF (from wordWeights)
    abbreviations.ts  // lazy dictionary; expansion = candidates; misread blocklist (LinkerToOtzaria)
    offsets.ts        // raw↔visible (countVisibleChars), BOM
  structure/
    headings.ts       // heading-rule table (daf/perek/siman/seif/halacha/pasuk/mishna/numbering) + DafTracker
    toc.ts            // TOC from seforim.db (tocEntry/tocText) or from <hN> in a file
    profiles.ts       // JSON profile: rules {daf|heading|target_switch|anchor}, validate, reset_on_unmatched
  strategies/
    byHeadings.ts     // heading → heading (state machine), gate ≥3 & ≥50%
    byDibur.ts        // DH extraction (BOLD/DASH/delimiter/כו') + contiguous-run search + dynamic threshold
                      // + cursor + tiers (full/partial/fuzzy/LCS) + SWDH + inheritance (שם/בא"ד)
    footnotes.ts      // Link-Notes: markers by tag/regex, chapter split on reset, rescue transition, diagnostics
    citations.ts      // source references: book alias → location → resolve via TOC; certain/uncertain
  resolve/
    books.ts          // title resolution: exact → matchKey → book_acronym → pickBook score + nameOverlap; tie ⇒ null
    refs.ts           // location → line (line_ref/TOC), range for chapter/daf with no verse/side
  score/
    confidence.ts     // logistic model + Platt (from link-generator), tiers auto/review/drop
    guards.ts         // F1–F19, page/daf contradiction, ambiguous numbers, monotonicity, quote uniqueness
  links/
    model.ts          // Link {src:{book,line0,range?,offsets?}, dst:{...}, type, direction, confidence, evidence, origin}
    dedupe.ts         // key: (path_2, l1, l2, start, end); merge with existing links (existing wins)
    recheck.ts        // re-check existing links: −2..+3 shift + Jaccard (OLM idea), source_hash
  io/
    linksJson.ts      // read/write _links.json (Conection/Connection, 1-based, direction by filename)
    validate.ts       // validateLinksForExport + generator compatibility (Link-Notes)
  batch/
    planner.ts        // folder/many books: target guess from filename, status + reason per book, override
    worker.ts         // Web Worker; incremental progress; abort
```

**עקרונות.**
- **כל אסטרטגיה מחזירה `Candidate[]` עם `evidence`.** שכבת `score` מחליטה. אף אסטרטגיה לא כותבת קישור ישירות.
- **שלוש דרגות:** `auto` (ביטחון לפחות 85 ובלי תיקו), `review`, `drop`. ברירת המחדל של אצווה: לייצא רק את `auto`.
- **סדר ההרצה לכל ספר:** כותרות (עוגן גס) → ד"ה בתוך חלון הכותרת → הפניות → הערות.
  - כל שכבה מצמצמת את חלון החיפוש של הבאה אחריה (כמו ה־`HALACHA_MULTIPASS_PLAN` של link-generator).
- **הסרת כפילויות מול קישורים קיימים:** קישור קיים (ידני) תמיד מנצח. קישור אוטומטי זהה מסומן "כבר קיים".
- **ביצועים:**
  - Web Worker;
  - מטמוני מילים עם תקרה;
  - sql.js עם zstd-dict ב־WASM לקריאת `line_content` בעצלתיים;
  - המילון הגדול נטען רק כשמפעילים התאמת טקסט.
- **בדיקות:**
  - fixtures של DhKey ו־RefKey;
  - קורפוס הזהב (164 מקרים);
  - קטלוג F1–F19 כתרחישים;
  - מקרי הקצה של §5 כבדיקות יחידה: מקף, לבית/בית, לא/לה, טו/טז, יה, עז, מ"א, BOM.
