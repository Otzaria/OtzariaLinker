## 1. כללי הברזל

ארבעה כללים שאסור לשבור. **כלל 1.1 נאכף בבדיקות שבקובץ** (§10); שלושת האחרים
הם משמעת שאין דרך לאכוף אוטומטית.

### 1.1 אפס תלות רשת

בקובץ **אין ולא יהיה** אף `<link>` חיצוני, `<script src>`, `fetch`, `XMLHttpRequest`
או `@import` לדומיין. הכול מוטמע:

| רכיב | איך מוטמע |
|---|---|
| אייקונים | `<symbol>` SVG בתוך בלוק ה-`<svg><defs>` שבראש ה־`<body>` (מקטע B) |
| פונטים | פונטי מערכת בלבד (`--font-ui`, `--font-book`) |
| sql.js | סקריפט מוטמע |
| WASM של sql.js | base64 ב־`window.__SQL_WASM_B64__`, מועבר כ־`wasmBinary` |
| JSZip | סקריפט מוטמע |
| LazySqlite | סקריפט מוטמע |

> ההיסטוריה: גרסה קודמת טענה את `Material Symbols Rounded` מ־Google Fonts. בלי
> אינטרנט הפונט לא נטען, ותגית `<span class="material-symbols-rounded">swap_horiz</span>`
> הוצגה כטקסט `swap_horiz`. **זו הסיבה שאסור להשתמש בפונט אייקונים.**

בדיקות `אין <link> חיצוני בקובץ` ו־`אין <script src> חיצוני` שומרות על זה.

### 1.2 קריאה בלבד

הכלי **לעולם** אינו כותב למסד הנתונים. `DbBookRepository` ו־`LazyDbBookRepository`
חושפים רק פעולות קריאה. הפלט היחיד הוא קבצים שהמשתמש מוריד.

### 1.3 מקור האמת לפורמט

[`קישורים-וכותרות.md`](https://github.com/Otzaria/otzaria-library/blob/b8301732db34be3ad89385a8c1ee2006156d2615/docs/%D7%A7%D7%99%D7%A9%D7%95%D7%A8%D7%99%D7%9D-%D7%95%D7%9B%D7%95%D7%AA%D7%A8%D7%95%D7%AA.md) שבמאגר `Otzaria/otzaria-library` הוא מקור האמת
לכל מה שנכתב לקבצים, והוא מתעדכן מעת לעת. שינוי בפורמט מתחיל שם, ורק אחר כך
ב־`Domain.ExportBuilder`.

**אין עותק מקומי של המסמך במאגר הזה, בכוונה.** עותק כזה מתיישן בשקט והופך
למקור אמת שקרי; עדיף לקרוא תמיד את הגרסה החיה.

### 1.4 קובץ אחד

הכלי חייב להישאר קובץ HTML יחיד, נייד, שנפתח בלחיצה כפולה. אין להוסיף שלב build.

<a name="2-ארכיטקטורה"></a>
## 2. ארכיטקטורה

תלות **בכיוון אחד בלבד**:

```
Config → Util → Data → Domain → Kit → UI → Dialogs → Boot
```

| שכבה | אחריות | מה אסור בה |
|---|---|---|
| **Config** | קבועים והגדרות משתמש | לוגיקה |
| **Util** | לוגר, DOM helpers, קבצים, אופסטים, גימטריה | ידע על קישורים |
| **Data** | קריאת SQLite/txt/JSON, אריזת ZIP | לוגיקה עסקית |
| **Domain** | המודל והחוקים: קישורים, טווחים, ייצוא, היסטוריה | **כל נגיעה ב־DOM** |
| **Kit** | רכיבי ממשק גנריים: דיאלוג, טוסט, שדות | ידע על קישורים |
| **UI** | מסכים, פאנלים, הבונה | לוגיקה עסקית (מאציל ל־Domain) |
| **Dialogs** | כל החלונות | — |
| **Boot** | חיווט אירועים ואתחול | לוגיקה |

`UI` ו־`Dialogs` מפנים זה לזה בזמן ריצה (`UI.show("help")` קורא ל־`Dialogs.renderHelp()`,
ו־`Dialogs` קורא ל־`UI.refreshAll()`). מה שמאפשר את זה הוא ש־**`UI` מזכיר את
`Dialogs` רק בתוך גופי פונקציות** — לעולם לא בזמן הערכת המודול. `Dialogs` ו־`Boot`
דווקא כן לוכדים `UI.ui` בזמן הערכה, ולכן הם מוגדרים אחרי `UI`. שבירת אחד משני
התנאים האלה תיצור `undefined` בזמן טעינה.

**חריגה מוצהרת:** `UI.buildLinksFromSelection` ו־`createFromSelection` מכילים כלל
עסקי — התרגום מבחירה במסך לרשומות קישור (יצירה מרובה, החלת תווית העוגן, קיצור
הטווח הקודם). זה נשאר ב־`UI` כי הוא תלוי כולו במצב התצוגה. כל כלל שאינו תלוי
בבחירה שייך ל־`Domain`.

### מבחן מהיר לשאלה "איפה לשים קוד חדש"

| השאלה | התשובה |
|---|---|
| האם זה משנה מה נכתב לקובץ? | `Domain.ExportBuilder` |
| האם זה חוק על קישור? | `Domain.LinkService` / `Domain.Ranges` / `Domain.Sefaria` |
| האם זה קריאה ממקור נתונים? | `Data` |
| האם זה נראה על המסך? | `UI` או `Dialogs` |
| האם זה כפתור שמחבר בין שניים? | `wire()` שבתוך `Boot` (פרטי) |

<a name="3-מפת-הקובץ"></a>
## 3. מפת הקובץ

הקובץ מסומן בכותרות ממוספרות. חיפוש `§` או המספר יביא אתכם ליעד.

| מקטע | תוכן |
|---|---|
| `<head><style>` A1–A16 | טוקנים ורכיבי עיצוב |
| `<svg>` B | ה־sprite של האייקונים |
| C1–C5 | HTML: סרגל עליון, מסך מקורות, מסך עורך, מסך עזרה, שכבות־על |
| D | ארבעת הסקריפטים המוטמעים (sql.js, WASM, JSZip, LazySqlite) — **אין לערוך ידנית** |
| E §1 | `Config` |
| E §2 | `Util` |
| E §3 | `Data` |
| E §4 | `Domain` |
| E §5 | `Kit` |
| E §6 | `UI` |
| E §7 | `Dialogs` |
| E §8 | `HELP_HTML` |
| E §9 | `Boot` |
| E §10 | `window.runSelfTests` |
| E §11 | `Boot.init()` — נקודת ההפעלה |

### עריכת הקובץ בלי לגעת בבלוקים הענקיים

שורות ה־base64 הן בנות מאות אלפי תווים ומקשות על עורכים. הדרך הבטוחה:

```bash
# חילוץ הבלוקים המוטמעים לקובץ נפרד (השורות בין <script>/* sql.js glue */ ל-</script> האחרון של LazySqlite)
grep -n 'sql.js glue\|LazySqlite — \|^</script>' index.html | head
sed -n '<from>,<to>p' index.html > /tmp/libs.html
# עורכים את שאר החלקים, ואז מרכיבים מחדש
cat part-a.html /tmp/libs.html part-c*.js > index.html
```

<a name="4-מערכת-העיצוב"></a>
## 4. מערכת העיצוב

הפלטה **אינה** "בהשראת אוצריא" — היא הפלטה של אוצריא בדיוק. היא הופקה מהקריאה שאוצריא
עצמה עושה:

```dart
// lib/theme/app_theme_data.dart
ColorScheme.fromSeed(
  seedColor: AppSeedColors.darkBrown,   // #2C1B02 — ברירת המחדל של אוצריא
  brightness: ...,
  dynamicSchemeVariant: DynamicSchemeVariant.tonalSpot,
)
```

התוצאה הודבקה כמשתני CSS ב־`:root` וב־`html[data-theme="dark"]`.
**להפקת פלטה חדשה** (אם משנים seed):

```dart
// dart run, עם package:material_color_utilities בלבד
final s = SchemeTonalSpot(sourceColorHct: Hct.fromInt(0xFF2C1B02), isDark: false, contrastLevel: 0);
print(MaterialDynamicColors.primary.getArgb(s).toRadixString(16));
// ...וכן לכל תפקיד
```

### מה עוד הועתק מאוצריא

| טוקן | ערך | מקור באוצריא |
|---|---|---|
| רדיוס | **8px בכל מקום** | `AppTokens.radius` — מקור אמת יחיד |
| מרווחים | 4 / 8 / 12 / 16 / 24 / 32 | `AppTokens.space*` |
| גדלי טקסט | 12 / 14 / 16 / 18 | `AppTokens.font*` |
| Hover | `primary` ב־8%, לחוץ/פוקוס 12% | `AppThemeData._*ButtonTheme` |
| רקע סרגל עליון | `surfaceContainerHigh` | `AppSurfaces.topBarBackground` |
| רקע דיאלוג | `surfaceContainerHigh` | `DialogThemeData` |
| מחוון לשונית | `secondaryContainer`, רדיוס 8 | `AppThemeData._tabBarTheme` |
| פריט נבחר | `primaryContainer` — 55% ברשימת הספרים, 45% בשורות טקסט | `AppSurfaces.selectedItem` (30%) — הוגבר כדי שייראה על רקע חם |
| רקע האפליקציה | בהיר: `#f6ede5`, כהה: שחור | `AppSurfaces.panelBackground` |
| טולטיפ | `surfaceContainerHigh` + `outlineVariant` + צל | `AppThemeData._tooltipTheme` |
| תפריט נפתח | `surfaceContainer`, elevation 3, פריט 36px, גופן 14, אייקון 18 | `AppMenuMetrics.create` |
| פריט נבחר בתפריט | `primary` + משקל 600 + ✓ מלא בקצה | `buildAppMenuRowContent` |

**אין לכתוב צבע קשיח בשום מקום מלבד שני בלוקי הטוקנים.** אם צריך גוון ביניים —
`color-mix(in srgb, var(--x) N%, transparent)`.

### גיוון טונלי מכוון

הפלטה של אוצריא רחבה יותר מ־`primary` בלבד, והכלי משתמש בה כדי להעביר מידע:

| מקום | גוון | למה |
|---|---|---|
| טור המקור | `primary` | חום־זהוב |
| טור היעד | `tertiary` | ירוק־זית — ההבחנה בין הטורים מיידית, בלי לקרוא |
| כרטיסי המקורות | primary / secondary / tertiary / neutral | ארבעה כרטיסים, ארבעה גוונים |
| סטטוס קישור | `tertiary` חדש · `warning` נערך · ניטרלי קיים | |
| דרגת ודאות | `tertiary` / `warning` / `error` | ודאי / כנראה / לבדיקה |

הטור מגדיר `--pane-accent`, `--pane-accent-container`, `--on-pane-accent-container`,
וכל מה שבתוכו (בחירת שורה, סימון קישור, תווית "פעיל") נגזר מהם. כדי להוסיף טור חדש
בגוון אחר — מגדירים את שלושת המשתנים על ה־`.pane` שלו, וזהו.

### רספונסיביות

נקודות השבירה, מהרחב לצר:

ארבע דרגות צפיפות (`html[data-density]`): `spacious` / (ברירת מחדל) /
`compact` / `dense`. כל אחת קובעת `--row-pad`, `--line-fs` ו-`--line-lh`.
גובה שורת הספר נגזר מהן ב-`UI.rowHeight`.

שלוש כותרות הטורים (`.pane-head`) בגובה קבוע 38px + גבול, כדי ששלושת הטורים
יתחילו באותה שורה בדיוק; כפתורי האייקון בתוכן מוקטנים ל-28px כדי לא לדחוף
את הגובה. במגע הכותרת גדלה ל-52px.

| רוחב | מה משתנה |
|---|---|
| ≥1700 | עמודות רחבות יותר |
| 1400–1700 | ברירת המחדל |
| 1200–1400 | עמודות צרות יותר |
| 1000–1200 | הכפתור "קישור אוטומטי" הופך לאייקון, שם המותג נעלם |
| ≤1000 | **ארבע העמודות נערמות** לפריסה אנכית |
| ≤700 | העזרה בריפוד מוקטן, טבלאות רחבות נגללות בתוך עצמן |
| ≤620 | לשוניות יורדות לשתי שורות במקום להיגלל |
| ≤560 | דיאלוגים מלאי-מסך, כרטיסים בעמודה אחת, פס השלבים מוסתר |
| גובה ≤640 | דיאלוגים ותפריטים נמוכים יותר (טלפון לרוחב, לפטופ ישן) |

בנוסף, `@media(pointer:coarse)` מגדיל את יעדי הלחיצה ל-44px (כפתורים משניים 40) ומכבה
טולטיפים (אין ריחוף במגע). גובה שורת הספר הוא היחיד שנקבע ב-JS
(`UI.rowHeight`) — הרשימה וירטואלית ולכן CSS לא יכול לקבוע אותו. הוא מתעדכן
בשינוי צפיפות וב-`resize`.

`.appbar` הוא תמיד `flex-wrap:wrap`, ו-`.pane` הוא תמיד `overflow:hidden` —
שני אלה מבטיחים שאין גלילה אופקית בשום רוחב.

**מפרידים ניתנים לגרירה בין העמודות אינם קיימים** — רוחבי העמודות נקבעים
בנקודות השבירה בלבד.

### מלכודות שנפתרו — לא לחזור עליהן

* **טולטיפ שמסתתר ב־`opacity`** מרחיב את שטח הגלילה של הדף וגורם לגלילה אופקית.
  הפתרון בקובץ: `display:none` + `@keyframes` עם `animation-delay`.
* **`.appbar` בלי `flex-wrap`** גולש כשיש הרבה כפתורים. עכשיו הוא תמיד `flex-wrap:wrap`.
* **`.pane` בלי `overflow:hidden`** נותן לתוכן לדחוף את עמודת ה־grid.
* **תכונה לוגית על צורה גרפית.** סימן הווי של ה־checkbox נבנה משני גבולות של ריבוע
  מסובב. שימוש ב־`border-inline-end` הפך אותו ב־RTL וייצר צורה שבורה. **לצורות
  גרפיות משתמשים בגבולות פיזיים** (`border-right`), ללוגיקת פריסה — בלוגיים.
* **`<select>` מובנה אינו ניתן לעיצוב** — מערכת ההפעלה מציירת את הרשימה הנפתחת,
  ולכן היא לא נראתה כמו אוצריא. הוחלף ב־`Kit.selectEl`. בדיקה עצמית מוודאת
  שאין אף `<select>` בעמוד.
* **גלילה שסוגרת תפריט פתוח.** מאזין `scroll` גורף סגר את התפריט בכל פעם שהיומן
  נגלל אוטומטית ברקע. עכשיו נסגר רק כשהגלילה מזיזה את העוגן עצמו.

<a name="5-האייקונים"></a>
## 5. האייקונים

כל האייקונים הם `<symbol>` ב־sprite, בגריד 24×24, בסגנון קו (`stroke`) בעובי אחיד —
מקביל ל־Material Symbols Rounded במשקל outlined.

```html
<!-- הגדרה -->
<symbol id="ic-search" viewBox="0 0 24 24"><circle cx="11" cy="11" r="6.5"/><path d="m20 20-4.2-4.2"/></symbol>
<!-- שימוש ב־HTML -->
<svg class="ic"><use href="#ic-search"/></svg>
```

בקוד: `Util.icon("search")` מחזיר מחרוזת HTML, `Util.iconEl("search")` מחזיר אלמנט.
הגדלים: `.ic` (20px), `.ic.sm` (16), `.ic.lg` (24), `.ic.xl` (32).

**להוספת אייקון:** מוסיפים `<symbol>` ל־sprite (בלי `fill` — הצבע מגיע מ־`currentColor`)
ומשתמשים בשמו. הבדיקה `כל האייקונים קיימים ב-sprite` תופסת `<use>` ששובר.

<a name="5b-תפריטים"></a>
## 5א. תפריטים ובוררים

בקובץ **אין ולו `<select>` אחד**. כל בורר הוא `Kit.selectEl(id, groups, value)` שמחזיר
כפתור בסגנון שדה טופס, ופותח `Kit.menu()` — תפריט צף שנבנה לפי מידות תפריט הלחיצה
הימנית של אוצריא.

```js
const sel = Kit.selectEl("kindSelect",
  [["מפרשים", [["commentary", "פירוש", "הערת עזר"]]],
   ["קישורים", [["reference", "הפניה"]]]], "commentary");
sel.addEventListener("change", () => console.log(sel.value));   // בדיוק כמו <select>
```

הכפתור המוחזר חושף `value` (get/set) ויורה אירוע `change` — כך שקוד שנכתב מול
`<select>` עובד בלי שינוי. `Kit.simpleSelect` הוא קיצור לרשימה בלי קבוצות.

`Kit.menu(anchor, {items, value, onSelect})` שימושי גם לבדו — לתפריטי פעולות. פריטים:
`{value, label, note, icon, divider, group, disabled, destructive, onSelect}`.

התנהגות שכבר מטופלת: ניווט מקלדת (חצים, Home/End, Enter, Esc), היפוך אוטומטי כשאין
מקום מתחת או בצד, סגירה בלחיצה בחוץ, וסגירה בגלילה — **רק** כשהגלילה מזיזה את העוגן.

<a name="6-מודל-הנתונים"></a>
## 6. מודל הנתונים

### Book

```js
{ id, source, dbBookId, title, path, lineCount, isSefaria, _lines, _repo, _lazyRepo }
```

`source ∈ OTZARIA_DB | PRIVATE_DB | UPLOADED_TXT | UPLOADED_FOLDER | PLACEHOLDER`.
`isSefaria` הוא `true` / `false` / `null` (לא ידוע).
`_repo` הוא repo סינכרוני (sql.js), `_lazyRepo` א־סינכרוני (LazySqlite) — לעולם לא שניהם.

### Link

```js
{
  id, status,                                  // NEW | EDITED | EXISTING | DELETED
  sourceBook, sourceLineIndex, sourceRangeEnd, // 0-based, כולל
  targetBook, targetLineIndex, targetRangeEnd,
  connectionType, heRef, ref1, ref2,
  anchor,   // {startVisible,endVisible,label}  ← נוצר במסך
            // {rawStart,rawEnd,label}          ← יובא מקובץ, נשמר כמות שהוא
}
```

**אינדקסים בזיכרון תמיד 0-based; בקובץ תמיד 1-based.** ההמרה מתבצעת בנקודה אחת בלבד —
`ExportBuilder.build` בכיוון אחד, ו-`idxOrNull` שבתוך `importJsonRecords` בכיוון השני.

`state.dedup` הוא `Set` של `sourceBook.id|srcIdx|targetBook.id|tgtIdx|type` שמונע כפילות.
כל שינוי בשדות האלה חייב לעבור דרך `LinkService.edit` שמתחזק אותו.

<a name="7-חוזה-הייצוא"></a>
## 7. חוזה הייצוא

`Domain.ExportBuilder.build()` בונה את הרשומות. סדר השדות קבוע ומכוון (diff קריא בגיט):

```
line_index_1  [line_index_1_end]  line_index_2  [line_index_2_end]
[start] [end]  heRef_2  [ref_1] [ref_2]  path_2  "Conection Type"
```

| כלל | איפה נאכף |
|---|---|
| `"Conection Type"` — n אחת | `Config.CONNECTION_TYPE_KEY` |
| 1-based בקובץ | `ExportBuilder.build` |
| שורת כותרת בקצה → הרשומה מדולגת | `ExportBuilder.build`, שער בתחילת הלולאה |
| `_end` נכתב רק אם גדול מההתחלה ותקין | `Ranges.isEffective` |
| `start`/`end` הם אופסטים גולמיים | `ExportBuilder.anchorOffsets` |
| הקישור חד־כיווני (מקור→יעד בלבד) | אין ייצור רשומה הפוכה |

הפלט כולל גם `problems[]` — מערך של `{level, msg, link}`. `level:"error"` מסמן דבר
שיפיל את הפייפליין השבועי; הוא מוצג באדום בדיאלוג הייצוא ובראש `_report.txt`.

<a name="8-טווחים"></a>
## 8. טווחים

### המודל

הקישור מעוגן ב**שורת ההתחלה**, ורק שורת ה**סיום** נשמרת בשדה נפרד — אחד לכל צד:
`line_index_1_end` לצד המקור, `line_index_2_end` לצד היעד. אין שדה "תחילת טווח".

> **באג היסטורי שלא לחזור עליו:** גרסה קודמת התייחסה לשני שדות ה־`_end` כאילו הם
> "תחילת הטווח" ו"סוף הטווח" של אותו צד. התוצאה: `line_index_1_end` שווה להתחלה
> (טווח מנוון), והשדה השני הוגדר על הצד הלא נכון — הגנרטור קישר רק את השורה הראשונה.
> חמש בדיקות עצמיות שומרות היום על הסמנטיקה הנכונה, כולל
> `רשומת טווח מכילה בדיוק 2 שדות אינדקס לצד היעד`.

### `Domain.Ranges`

| מתודה | תפקיד |
|---|---|
| `markers(book, side, exclude)` | אינדקסי ה"סמנים" בספר — לפי `Config.rangeEndBasis` |
| `suggestEnd(book, start, side, exclude)` | שורה אחת לפני הסמן הבא, אחרת עד סוף הספר |
| `validateSide(link, side)` | אזהרות: סיום הפוך / מחוץ לספר / שורת כותרת |
| `isEffective(link, side)` | האם ה־`_end` ייכתב בפועל |
| `trimPrevious(book, side, newStart)` | קיצור הטווח הקודם שלא יבלע את החדש |
| `autoFillBook(book, side, opts)` | "כל טווח עד הקישור הבא" — פעולת אצווה |
| `revert(changes)` / `reapply(changes)` | undo/redo לשתי הפעולות האחרונות |

`trimPrevious` ו־`autoFillBook` מחזירות `changes[]` עם `prev` ו־`next` לכל שינוי — זה מה
שמאפשר לרשום אותן ב־`History` בלי לצלם את כל המצב.

### בשכבת ה־UI

`UI.effectiveEnd(side)` מחשב את הסיום לפי סדר עדיפויות:
**ערך שהמשתמש הקליד → סימון רציף (Shift) → הצעה אוטומטית**.
זה המקום היחיד שקובע איזה ערך נכנס לשדה ומה מוצג בתצוגה המקדימה (`.line-row.in-range`).

<a name="9-עוגנים-ואופסטים"></a>
## 9. עוגנים ואופסטים

המשתמש מסמן על הטקסט המוצג; הקובץ דורש אופסט **גולמי** (כולל תגיות). שתי הפונקציות
ב־`Util` הן היפוך זו של זו:

```js
rawOffsetFromVisible(rawHtml, visibleIndex) → rawIndex
countVisibleChars(rawHtml, rawIndex)        → visibleIndex
```

הכללים (זהים ל־`buildLinkAnchor` בגנרטור):
* תג `<…>` נבלע ואינו נספר.
* ישות `&…;` נספרת כתו גלוי **אחד**.
* אחרי הגעה ליעד מדלגים על תגים פותחים נוספים, כדי שהאופסט יצביע על הגליף.

הדוגמה המאומתת מהתיעוד: `"אב <b>ג</b> דה"`, התו הגלוי `ג` במקומות 3..5 → `start=6, end=12`.

**לכידת הסימון** (`UI.captureAnchor`) משתמשת ב־`Range` אמיתי ולא ב־`indexOf`, כדי שגם
מילה שחוזרת כמה פעמים באותה שורה תיתפס במקום הנכון.

**עוגן שיובא מקובץ** נשמר כ־`{rawStart, rawEnd}` ומיוצא כמות שהוא, בלי המרה כפולה.

<a name="9b-heb"></a>
## 9א. השוואת טקסט עברי — `Util.Heb`

מודול קטן להשוואת **כותרות** (לא משפטים). מאומץ מ־`src/utils/fuzzyUtils.ts` של
[`otzaria-link-generator`](https://github.com/Otzaria) — הרעיון והספים משם, המימוש
נכתב מחדש ומצומצם.

| פונקציה | תפקיד |
|---|---|
| `stripNikud(s)` | הסרת `U+0591–U+05C7`. משמש גם בחיפוש החופשי בפאנלים |
| `normalize(s)` | ניקוד + גרשיים + ראשי תיבות מבניים + פיסוק + רווחים |
| `stem(w)` | הסרת אות שימוש אחת, אם נשאר שורש ≥3 |
| `skeleton(w)` | הסרת ו/י; סופיות `א↔ה`, `ן↔ם` מאוחדות (מ־3 אותיות) |
| `levenshtein(a,b,max)` | מרחק עריכה עם יציאה מוקדמת |
| `wordSimilarity(a,b)` | 0..1 — מדויק 1.0 · שורש 0.92 · כתיב 0.88 · fuzzy 0.7–0.95 |
| `phraseSimilarity(a,b)` | 0..1 — התאמת מילים חמדנית, מנורמלת לצד הארוך |

**ספי הגמישות** (`maxEdits`) הם החלק הקריטי: מילה עד 3 אותיות חייבת התאמה מדויקת,
4–6 מרשות שינוי אחד, 7 ומעלה שניים. בלי הסף הקצר, `לא` ו־`לה` נחשבות זהות.

**סטייה מודעת מהמקור:** שם הביטוי הוא `^[ובלמשכה]+` (חמדן), ולכן `לבית` מקלף שתי
אותיות, נשאר `ית` באורך 2, השומר מבטל את הקילוף והמילה לא מתקצרת כלל. כאן הביטוי
מקלף **אות אחת** — מקיים את הכוונה ואינו סובל מזה.

מילון ראשי התיבות כאן מכוון להיות **קטן וחד־משמעי** (17 ערכים מבניים: סי׳, ס"ק, פ׳,
הל׳…). המילון המלא של המחולל (400+ ערכים, כל אחד עם כמה הרחבות אפשריות) מתאים לניתוח
משפטים, לא להשוואת כותרות — ובקובץ יחיד הוא גם היה מוסיף מגה־בייט.

השימוש: `Domain.structuralMatch(..., {fuzzy:true, threshold:0.82})`. כל התאמה חוזרת עם
`score` שמוצג בתצוגה המקדימה בשלוש דרגות (≥0.95 ודאי, ≥0.85 כנראה, מתחת — לבדיקה).

<a name="10-ספריא-ו-ref"></a>
## 10. ספריא ו־`ref`

`Domain.Sefaria` מיישם את פרק 9 בתיעוד. `checkLink()` מחזיר בעיות עם `code` שתואם
לשגיאות הפייפליין:

| code | מתי |
|---|---|
| `new_target_ref_required` | היעד ספריא ואין `ref_2` |
| `new_source_ref_required` | המקור ספריא ואין `ref_1` |
| `both_refs` | שני ה־refs יחד |
| `sefaria_both` | שני הצדדים ספריא |
| `ref_2_side_classification_changed` | יש `ref_2` אבל היעד אינו ספריא |

הזיהוי, בסדר עדיפויות:
1. רשימת `sefaria_he_titles.txt` שהמשתמש טען — **התאמת מחרוזת מדויקת** על שם הקובץ
   בלי סיומת (`Domain.pathStem`). בלי נרמול גרשיים — זו בדיוק ההתנהגות של הפייפליין,
   כולל "מלכודת הגרשיים".
2. טבלת `source` במסד, אם קיימת.
3. `null` — לא ידוע, ואז אין אזהרה.

<a name="11-מנוע-הקריאה-העצלה"></a>
## 11. מנוע הקריאה העצלה

`seforim.db` שוקל כ־8GB. דפדפן לא יכול להחזיק `ArrayBuffer` בגודל כזה, ולכן
`new SQL.Database(bytes)` בלתי אפשרי.

`window.LazySqlite` הוא מנוע JS טהור שקורא SQLite **read-only** ישירות מהקובץ דרך
`File.slice(offset, length)` — רק העמודים שנחוצים (16KB כל אחד). יכולות: פענוח header,
varint, records, serial types, סריקת טבלה, `scanRange` (טווח rowid), `rowById`,
`indexEqFirstCol` (seek באינדקס עם גיזום), ו־overflow pages.

`Data.openSqlite` בוחר מסלול: קובץ ≤ `Config.lazyThresholdMb` (700 כברירת מחדל) → sql.js
מלא; גדול יותר → LazySqlite. שני המסלולים חושפים את אותו ממשק ל־Domain, כך שכל שאר
הקוד לא יודע באיזה מנוע הוא משתמש.

**ביצועים מדודים מול `seforim.db` האמיתי:** רשימת 7,293 ספרים ≈ 130ms;
שורות של ספר ≈ 30–100ms שקוראות כ־1MB מהדיסק.

**להוספת שאילתה:** מוסיפים מתודה ל־`LazyDbBookRepository` שמשתמשת ב־`indexEqFirstCol`
/ `scanRange` / `rowById`. כתיבה — לא נתמכת בכוונה (ראו [כלל 1.2](#1-כללי-הברזל)).

### מה שהבדיקות בקובץ אינן יכולות לבדוק

רספונסיביות, ניגודיות צבע, יעדי מגע ובקשות רשת דורשים דפדפן אמיתי. הדרך
לבדוק אותם בלי להוסיף קבצים למאגר: Chrome headless דרך CDP, מסקריפט חד־פעמי
מחוץ למאגר (Node 22+ כולל `WebSocket` מובנה, אין צורך ב-npm install):

```

GET http://127.0.0.1:9333/json/list   → webSocketDebuggerUrl
Page.navigate → Runtime.evaluate("JSON.stringify(window.runSelfTests())")
```

מה שנבדק כך לפני השחרור: 14 גדלי מסך × 2 ערכות × 6 מסכים (גלישה אופקית,
אלמנט מחוץ למסך, יעד מגע, ניגודיות WCAG AA, תוכן חתוך), רשת מנותקת,
`localStorage` חסום, והרצת חבילת הבדיקות על העותק העצמאי שהכלי מייצר.

מלכודות: `Emulation.setDeviceMetricsOverride` יורה `resize` באיחור של פריים
וסוגר תפריט פתוח — יש להמתין ~250ms; ומדידה בזמן אנימציית הכניסה של דיאלוג

2. הקובץ נפתח מ־`file://` בלי אינטרנט, והאייקונים מוצגים כאייקונים.

4. אם נגעתם בייצוא — ייבוא↔ייצוא של אותו קובץ חייב לצאת זהה.

<a name="13-תרחישי-הרחבה-נפוצים"></a>
## 13. תרחישי הרחבה נפוצים

### הוספת סוג קשר חדש

`Config.REFERENCE_TYPES` (או `COMMENTATOR_TYPES`) — שלשה `[ערך גולמי, תווית, הסבר]`.
הערך הגולמי חייב להתאים ל־`ConnectionType.fromString` בגנרטור. אם הוספתם ל־
`COMMENTATOR_TYPES` — עדכנו את הבדיקה `שמונה סוגי מפרש בדיוק`.

### הוספת מבנה קישור חדש

`Config.LINK_KINDS` — אובייקט עם `id`, `label`, `srcRange`, `tgtRange`, `anchor`,
`short`, `desc`, `example`, `autoDesc`. שאר הקוד נגזר מהדגלים האלה בלבד: הבונה,
התצוגה המקדימה, `buildLinksFromSelection` והיצירה האוטומטית.

### הוספת הגדרה

`Config.DEFAULTS` + שורה בדיאלוג `Dialogs.settings()`. אם ההגדרה משפיעה על התצוגה —
לקרוא ל־`Boot.applyAllSettings()` אחרי השינוי.

### הוספת שדה חדש לרשומת הייצוא

1. לעדכן קודם את מסמך הפורמט במאגר `otzaria-library` (ראו §1.3).
2. להוסיף למודל ב־`LinkService.build` ול־`snapshot`/`applySnapshot`.
3. לכתוב ב־`ExportBuilder.build` **במקום הנכון בסדר השדות**.
4. לקרוא ב־`importJsonRecords`.
5. להוסיף שדה ב־`Dialogs.editLink` ובגוש "מתקדם" של הבונה.
6. להוסיף בדיקה עצמית.

<a name="14-פערים-ידועים"></a>
## 14. פערים ידועים

* **עוגנים וטווחים של קישורים קיימים במסלול העצל** — במסלול `LazySqlite` נקראים רק
  סוג הקישור ושורות הקצה. `link_anchor` / `link_range` אינם נקראים (יקר: seek נוסף לכל
  קישור). רלוונטי רק לספרי בסיס גדולים; לספרים אישיים אין קישורים קיימים.
* **פורמט ה־Map של DictaToOtzaria** (`{שורה: [{start,end,refs}]}`) אינו נתמך בייבוא.
* **ייצוא CSV** אינו תומך בטווח ובעוגן — הוא פורמט הקלט של ספריא, לא של אוצריא.
* **אין ולידציה מקוונת של `ref_2`** מול ספריא עצמה. הכלי מאמת רק את *נוכחות* השדה
  ואת סיווג הצד; נכונות המחרוזת היא באחריות הכותב.

### פערים פנימיים (קוד)

* **פאנלי הטקסט אינם וירטואליים** כמו רשימת הספרים. `renderPane` בונה מחדש את כל
  החלון המוצג בכל רענון, והחלון רק גדל (`goToLine` מרחיב אותו). קפיצה לשורה 40,000
  ואז לחיצה בונה 40,000 שורות מחדש. תיקון: וירטואליזציה, או עדכון ממוקד של
  `aria-selected` במקום רינדור מלא.
* **`runMatches` ריבועי בשני מקומות** — חיפוש ההתאמה הבאה (`Array.find` על מערך
  ממוין) וחישוב `computeHeRef` לכל התאמה (סורק מההתחלה). מורגש מעל ~5,000 התאמות.
* **סריקת `link_anchor`/`link_range` המלאה** ב-`DbBookRepository` נשמרת לכל ספר
  מחדש. השער הוא מספר הקישורים של הספר, לא גודל הטבלה.
* **היומן ב-DOM אינו חסום** בגודל, בעוד המאגר בזיכרון חסום ל-5,000 שורות.
* **`GlobalIndex` עם `includeDb`** טוען את כל שורות הספרייה לזיכרון ואינו משחרר.
* **`PRISTINE_HTML`** מחזיק עותק מלא של הקובץ (1.4MB) לאורך כל הסשן, בשביל כפתור
  "שמירת עותק עצמאי".
